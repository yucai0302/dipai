## 1. 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 形态 | 单个 `index.html` | 双击即可玩，方便发给朋友；无构建、无依赖、可离线 |
| 渲染 | 原生 HTML + CSS + JS | 页面只有一个 3×3 棋盘和一个操作区，不需要框架 |
| 翻牌动画 | CSS 3D `transform: rotateY` + `preserve-3d` | 性能好、代码少、质感稳定 |
| 状态管理 | 一个 `state` 对象 + `render()` 同步 DOM | 9 张牌的规模，不需要响应式框架 |

## 2. 数据模型

```js
state = {
  phase: 'setup' | 'pickA' | 'pickB' | 'reveal' | 'revealing' | 'bid' | 'decide' | 'deal' | 'showdown' | 'over',
  values:  ['10','50', ...],        // 9 个原始牌面，顺序即价值顺序（第 1 行最便宜）
  cards:   [{ value, rank, revealed }], // 洗牌后的 9 张；rank 保留写牌时的行号
  aBase:   3,                       // A 的底牌位置，-1 表示未选
  bBase:   7,                       // B 的底牌位置＝最后一张被 A 翻开的牌，摊牌时才确定
  batch:   0,                       // 已完成的翻牌轮次 0..6，第一轮 2 张、之后每轮 1 张
  need:    0,                       // 本轮还要点开几张
  bids:    [{ round, cards, price, decision }],
  pending: 300,                     // 当前待确认的报价
  numeric: true,                    // 九张是否全为数字（决定要不要算差价）

  // v1.1 新增
  mode: 'local' | 'ai',             // 本地双人 / 人机对战
  humanRole: 'A' | 'B',             // 人机模式下人类扮演的角色
  level: 1 | 2 | 3,                 // 简单 / 普通 / 困难
  tutorial: false,                  // 是否教学模式
  setupValues: null,                // 进对局前设置页的内容，回来时还原
  aiTimer: null                     // 电脑行动的唯一计时器
}
```

`isAI(role) = mode === 'ai' && humanRole !== role`，全流程只靠这一个判断决定「这一侧是不是电脑」。

`state.bids[i].decision`：`null / 'accept' / 'reject' / 'pass'`

轮次由牌数推导：9 张 − A 的底牌 1 张 = 8 张可翻；第一轮 2 张、之后每轮 1 张（共 6 轮报价），最后一次拒绝后 A 再翻开最后一张，这张就是 B 的底牌。

## 3. 状态机

```
setup ──▶ pickA ──A选底牌──▶ reveal ──A点选 2 张──▶ revealing ──▶ bid ──报价──▶ decide
                              ▲                                                     │
                              │                                                     ├─接受──▶ deal ──▶ over
                              └──────── 拒绝且 batch < 6（每次翻 1 张）─────────────┤
                                                                                    └─拒绝且 batch = 6──▶ reveal(最后一张)──▶ showdown ──▶ over
```

- `reveal`：A 直接点牌面翻开，不是随机；本轮 `need` 张点满才进入报价。
- `revealing`：收尾动画中，禁用交互，避免连点。
- `finalFlip`：最后一次报价拒绝后，`need = 1`、只允许点最后一张；翻开的这张记为 `bBase`。
- `deal / showdown`：底牌翻面动画期间（约 0.8s）后再弹出结果。
- `showdown`：A 的底牌翻开，与 `bBase` 那张按 `rank` 比大小（内容相同则流局）。
- 人机模式下，`pickA / reveal / bid / decide` 只要对应一侧 `isAI(role)` 为真，就由计时器自动推进（选牌 1s、翻牌 430–650ms、报价 1.0–1.6s、决定 1.3–1.9s），人类一侧照旧等待点击/输入。

## 4. 关键实现

### 4.1 洗牌
Fisher–Yates，保证每个位置等概率：

```js
for (let i = a.length - 1; i > 0; i--) {
  const j = Math.floor(Math.random() * (i + 1));
  [a[i], a[j]] = [a[j], a[i]];
}
```

### 4.2 翻牌
卡片是 `<button class="card">`，内部三层：

```
.card            perspective: 1000px
└ .card-inner    transform-style: preserve-3d  +  transition
  ├ .face.back   backface-visibility: hidden（深墨色，带斜纹与内框）
  └ .face.front  rotateY(180deg)（纸白牌面，衬线大字）
```

加 `.is-flipped` → `rotateY(180deg)`，只改 class，不改结构，动画自然。

### 4.3 候选价值池
「剩余可能」= 全部 9 个值 **减去** 已翻开的值（多重集相减，支持重复牌面）：

```js
const remain = multiset(values) - multiset(revealedValues)
```

每翻开一张就实时更新，B 报价时看到的参照系始终准确。池子按写牌的原始顺序排列（`values.indexOf`），文字牌也保持「越贵越靠下」。

### 4.4 结算与摊牌
- 成交（九张全为数字）→ 计算 `差价 = 成交价 − 底牌价值`，文案区分「A 赚 / B 赚 / 平手」。
- 成交（存在文字牌）→ 只展示成交价与底牌内容，不做数值比较。
- 摊牌（一路拒绝）→ 两张底牌一起翻开，按 `rank`（写牌时的行号）比大小：内容相同 → 流局；否则 `rank` 大的一方是赌王。这样文字牌也能比。

### 4.5 防误触
- 动画期间 `phase = 'revealing'`，所有入口函数先校验 phase。
- 报价输入只接受正数，回车即提交（桌面端自动聚焦）。
- 电脑行动统一走一个 `later(fn, ms)` 计时器（`state.aiTimer`），「再来一局 / 换一组牌」先 `clearAI()`，避免上一局的定时器打到新一局。
- 每个电脑动作的回调里都重新校验 `phase` / `isAI(role)`，过期回调直接丢弃。

### 4.6 电脑对手

**信息对等**：电脑不读底牌。对所有人来说，未翻开的牌（A 的底牌、还没翻的、最后那张）是等概率候选，所以估值统一用它们的均值：

```js
poolStats() → { ev: 未翻开牌的平均值, cv: 标准差 / 平均值 }
```

**电脑当 B（出价）**：以 `ev` 为基准打折，轮次越靠后折扣越小，估值越分散压得越低。

```js
prog = batch / MAX_BATCH
简单: f = 1.04 + 0.16·prog        ±14% 噪声   // 常常出到均价以上，人类 A 容易赚
普通: f = 0.80 + 0.16·prog        ±8%  噪声
困难: f = 0.56 + 0.18·prog − min(0.12, max(0, (cv−0.4)·0.2))   ±4% 噪声
报价 = nicePrice(ev · f · (1 ± 噪声))   // 按量级取整（100 / 10 / 1）
```

**电脑当 A（决定）**：报价高于自己对底牌的估计就成交，否则继续赌。阈值 = `ev · th`。

```js
简单: th ≈ 0.76     (±8% 噪声)   // 容易接受低价
普通: th ≈ 0.96     (±5%)
困难: th ≈ 1.10     (±4%)，估值很集中（cv < 0.25）时再降 0.08
```

**电脑选牌 / 翻牌**：牌背对电脑同样不可见，所以随机选、随机翻是最优解；用 430–650ms 的间隔逐张翻，让人类看清发生了什么。

**思考态**：报价前 1.0–1.6s、决定前 1.3–1.9s 的延迟，面板显示「电脑在出价 / 在考虑」＋跳动的三个点，避免瞬间出结果。

### 4.7 教学模式

- 进入时固定一组数字牌（`DEFAULTS`），人类当 A、电脑当 B、难度简单。
- 顶部 `#coach` 按 phase 显示 6 个步骤的讲解（选底牌 → 第一轮翻两张 → 报价 → 接受/拒绝 → 最后一张 → 结算），跟着对局自动翻页。
- 「退出教学 · 回首页」直接调用 `backToSetup()`：清掉电脑计时器、关掉牌局与讲解条、把设置页恢复成进教学前的牌面（教学用的固定牌不会写回设置页），并保持「人机对战」选中。


## 5. 视觉方案

**方向：中式纸感 + 编辑排版**。整体像一张裱好的纸，而不是「科技感 App」。

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--paper` | `#F2EDE3` | 底色，暖纸 |
| `--paper-2` | `#FBF7EF` | 牌面、面板 |
| `--ink` | `#17140F` | 主文字、牌背 |
| `--muted` | `#8B8272` | 说明文字 |
| `--line` | `#D8D0C0` | 分隔线、描边 |
| `--vermilion` | `#B03A2B` | 印章色，只用于角色标签与结算印章 |
| `--gold` | `#9E7B3C` | 底牌专属标记 |

- **字体**：正文用苹方/思源黑；数字用 Georgia 衬线，拉开「价签」的感觉。
- **版式**：顶部一条墨线分隔；标题字距放大；大量留白；不使用圆角卡片堆叠。
- **纹理**：SVG `feTurbulence` 噪点 + 径向暗角，避免纯色平面的廉价感。
- **动效**：发牌时 9 张依次错位落入（每张 40ms 延迟）；翻牌 680ms 缓动；成交时盖一枚朱红印章。
- **克制**：全站只有一个强调色、一个装饰印章，其余靠间距和字重区分层次。
